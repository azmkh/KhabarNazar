# Roman Urdu fake news detection (XLM-RoBERTa)

The text module of **KhabarNazar**. It classifies a Roman Urdu news article as **real** or **fake**, using `xlm-roberta-base` fine-tuned on a Roman Urdu dataset that we built.

## Dataset

8,267 Urdu news articles from four public datasets, transliterated to Roman Urdu with Claude (an LLM). The real/fake labels come from the original datasets.

| Source | Real | Fake | Total |
|---|---|---|---|
| Bend the Truth | 496 | 398 | 894 |
| FIRE 2021 (UrduFake) | 448 | 250 | 698 |
| Ax-to-Grind Urdu | 1,238 | 1,237 | 2,475 |
| Hook and Bait Urdu | 2,100 | 2,100 | 4,200 |
| **Total** | **4,282** | **3,985** | **8,267** |

Columns: `id`, `source_dataset`, `original_text` (Urdu script), `label`, `roman_text`.

**The article text is not in this repository.** The source datasets belong to their authors, so we don't redistribute them. `outputs/split_ids.csv` lists which article ids are in each split, so anyone with the data can rebuild the exact split.

## Split

80/10/10 into train (6,615), validation (826) and test (826), stratified by source and label (`notebooks/01_make_splits.ipynb`).

Near-duplicate articles are grouped (word-trigram Jaccard ≥ 0.5) and each group stays in one split. In Bend the Truth and FIRE, most fake articles are a one-word edit of a real one. Splitting such a pair across train and test would inflate the scores. 155 groups were found.

## Results (test set)

`xlm-roberta-base`, one run (seed 42), trained on a Colab T4 GPU for 5 epochs (about 58 minutes). The best validation macro-F1 was 0.840, reached at epoch 5.

| Source | n | TF-IDF + LR macro-F1 | XLM-R accuracy | XLM-R macro-F1 |
|---|---|---|---|---|
| **All** | 826 | 0.820 | 0.833 | **0.833** |
| Ax-to-Grind | 247 | 0.793 | 0.838 | 0.838 |
| Hook and Bait | 420 | 0.895 | 0.879 | 0.878 |
| Bend the Truth | 89 | 0.658 | 0.663 | 0.662 |
| FIRE | 70 | 0.623 | 0.757 | 0.722 |

Fake class: precision 0.813, recall 0.850, F1 0.831.

From a single run, XLM-R is only 1.3 points above the baseline overall. That gap is within run-to-run variation, so it needs several seeds before we can claim XLM-R is better. Both models are weakest on Bend the Truth, where most fakes are one-word edits of real articles.

Full numbers: `outputs/metrics.json`. Plots: `outputs/training_curve.png`, `outputs/confusion_matrices.png`.

## How to reproduce

1. Put `khabarnazar_roman_urdu_dataset.csv` in `data/` and run `notebooks/01_make_splits.ipynb`. It creates `data/splits/{train,val,test}.csv`.
2. Upload the three split files to Google Drive at `MyDrive/KhabarNazar_text/data/splits/`.
3. Open `notebooks/02_train_xlmr.ipynb` in Google Colab, choose a T4 GPU runtime, and run all cells (about 30 to 45 minutes).

Settings: max length 512 tokens, effective batch 16, learning rate 2e-5, up to 5 epochs with early stopping on validation macro-F1, seed 42.

## Running on a GPU computer

The same notebook runs outside Colab. It reads `data/splits/` and writes `model/` and `outputs/` inside this folder. It picks a batch size from the GPU's memory and keeps the effective batch at 16.

1. Check that the NVIDIA driver works: `nvidia-smi` should list the GPU and a "CUDA Version".
2. Create an environment (Python 3.10 to 3.12):
   ```bash
   cd text_module
   python -m venv .venv
   source .venv/bin/activate          # Windows: .venv\Scripts\activate
   ```
3. Install PyTorch **with CUDA** first. Get the exact command for your system from pytorch.org (Get Started), for example:
   ```bash
   pip install torch --index-url https://download.pytorch.org/whl/cu121
   ```
   Then install the rest:
   ```bash
   pip install -r requirements.txt jupyter
   ```
4. Check that the GPU is visible: `python -c "import torch; print(torch.cuda.is_available())"` should print `True`.
5. Run `jupyter notebook`, open `notebooks/02_train_xlmr.ipynb` and run all cells.

The first run downloads `xlm-roberta-base` (about 1.1 GB) from Hugging Face, so the computer needs internet access.

## Limitations

- **Transliteration by an LLM.** Roman Urdu was generated by Claude, not written by people. _Quality check: N random rows were read by a native speaker, error rate X%._
- **Length bias in FIRE.** Real FIRE articles are longer than fake ones (median 248 vs 167 words). Word count alone reaches 0.59 macro-F1 on FIRE, so part of any FIRE score may come from length.
- **Small per-source test sets.** Bend the Truth (89) and FIRE (70) test scores have wide error margins.
- **Truncation.** Articles longer than 512 tokens are cut (5.4% of training articles overall). Bend the Truth (median 389 tokens) and FIRE (median 312) are affected most: their longest 10% are over 860 tokens.

## Source datasets

- Bend the Truth: Amjad et al., "Bend the Truth: Benchmark dataset for fake news detection in Urdu language and its evaluation", *Journal of Intelligent & Fuzzy Systems*, 2020.
- FIRE 2021 UrduFake shared task: Amjad et al., "Overview of the shared task on fake news detection in Urdu at FIRE 2021".
- Ax-to-Grind Urdu: Harris et al., "Ax-to-Grind Urdu: Benchmark dataset for Urdu fake news detection", 2023.
- Hook and Bait Urdu: Harris et al., "Hook and Bait Urdu: A large-scale benchmark dataset for Urdu fake news detection".
